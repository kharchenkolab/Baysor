# Baseline: `bugfixes-35e8a7e` (noise floor, 6 threads × 3 replicates)

Official noise-floor baseline of the Baysor benchmark suite for the
**Release build of branch `bugfixes` at commit `35e8a7e`**
(`--label bugfixes-35e8a7e`, binary
`/home/vpetukhov/.bb/thread-storage/thr_cpwic2f6q3/baysor-bugfixes/build-rel/baysor`),
created by task BENCH-BASELINE. Use it with
`compare.py --expect same|improved` (see
[`../../README.md`](../../README.md) → "How to test a change").

## Contents and configuration

| | |
|---|---|
| datasets | **78** = 51 simulated + 27 real = 65 quick + 13 full |
| threads | 6 (`OMP_NUM_THREADS=6` for every replicate) |
| replicates | 3 per dataset (all tiers — the 10 h full-tier budget was **not** exceeded, see below) |
| timeout | 1800 s per quick replicate, 5400 s per full replicate (recorded as failures; none observed) |
| cellAdmix audit | on for every real replicate; rep0 is quick-clustered once, replicates 1–2 transfer rep0's typing; `baseline.py create` stores rep0's `celltypes.parquet` + the `fixed_pairs.json` taken from rep0's audit, so later runs compare on the **same typing and pair set** via `run.py --celltypes-from bugfixes-35e8a7e` |
| WTX datasets | `cosmx_wtx_colon_{quick,full}` keep `--cluster-method louvain` through `meta.baysor.extra_args` (the default ICA/mrf init does not scale to the ~19 k-gene crop) |

Timing estimate made from a 4-dataset sample (1 replicate each, measured
before committing to the full schedule):

| sampled dataset | wall/rep |
|---|---|
| `cosmx_wtx_colon_full` (3.0 M molecules, 19 k genes) | 1696 s |
| `xenium_pancreas_377_full` (2.0 M) | 355 s |
| `strec_dense_s2_xenium_full` (1.0 M, sim) | 195 s |
| `xenium_lung_cancer_admix` (0.55 M) | 95 s |

Extrapolated full tier ≈ 1.5 h/rep → **≈ 4.5–5.2 h for 3 replicates**, i.e.
below the ~10 h threshold from the task — so the fallback (1 replicate for
non-needed full datasets) was **not triggered** and **every full dataset got
3 replicates**. (Note: all 11 real full datasets are `admixture_capable`, so
the literal fallback rule would in any case have kept 3 replicates on them;
only the 2 existing sim full datasets exist beyond them.) The quick tier ran
≈ 40–50 min/rep → ≈ 2.5–3 h for 3 replicates.

**Measured totals** (sum of per-dataset mean wall times over the 78
finished datasets):

| tier | datasets | Σ wall/rep | × 3 replicates |
|---|---|---|---|
| quick | 65 | 3074 s (0.85 h) | **2.56 h** |
| full | 13 | 4450 s (1.24 h) | **3.71 h** |
| all | 78 | 2.09 h | **6.27 h** (observed ≈ 7 h wall incl. audits/metrics; zero failures, zero timeouts) |

Slowest datasets: `cosmx_wtx_colon_full` 1623–1696 s/rep (louvain on 19 k
genes), `xenium_prime5k_ovarian_full` ~684 s/rep, `cosmx_nsclc_lung5_rep1_full`
~385 s/rep, `xenium_pancreas_377_full` ~340 s/rep; heaviest quick datasets
are the `g5000` panel ablations (~210–255 s/rep). Peak RSS: 3.2 GB
(`cosmx_wtx_colon_full`), all others ≤ 2.4 GB.

**Metrics definitions:** the committed JSONs were (re)computed with
`recompute_metrics.py` after cherry-picking `4d160ae` (AMI returns NaN above
3000 labels — sklearn's EMI term made full-sim metrics take hours). AMI is
informational; no gate uses it.

## Reproduction

```bash
export BAYSOR_BENCH_DATA=/home/vpetukhov/Projects/Baysor/.bench-data
PY=.deps/bench/bin/python
B=/home/vpetukhov/.bb/thread-storage/thr_cpwic2f6q3/baysor-bugfixes/build-rel/baysor

# quick tier, 3 replicates
$PY benchmarks/harness/run.py --baysor $B --datasets quick \
    --run-id benchbase-b --replicates 3 --threads 6 --timeout 1800 \
    --label bugfixes-35e8a7e
# full tier, 3 replicates (phases reuse finished replicates)
$PY benchmarks/harness/run.py --baysor $B --datasets full \
    --run-id benchbase-b --replicates 3 --threads 6 --timeout 5400 \
    --label bugfixes-35e8a7e
# freeze + summarize (recompute first if the metric definitions changed)
$PY benchmarks/harness/recompute_metrics.py --run benchbase-b
$PY benchmarks/harness/baseline.py create --run-id benchbase-b \
    --name bugfixes-35e8a7e
$PY benchmarks/harness/vendor_audit.py --baseline bugfixes-35e8a7e \
    --datasets 'xenium_*_admix'      # vendor rate on the same typing/pairs
$PY benchmarks/harness/baseline_summary.py --baseline bugfixes-35e8a7e
```

The actual schedule ran the quick tier and a 4-dataset full-tier sample
first; the sample's replicate 0 was reused by the full-tier phase through
`--skip-existing` (only when status, binary sha256, thread count and scale
factor matched).

## Files

* `<dataset>.json` (committed) — full `metrics.json` per dataset plus the
  `baseline` block: flavour, ok-replicate count, assignment sha256 per
  replicate, cellAdmix typing/pair sha256, binary sha256 + label, input
  content hashes;
* `SUMMARY.md` (committed) — generated by `harness/baseline_summary.py`;
* assignment tables, `celltypes.parquet`, `fixed_pairs.json` (NOT committed)
  under `$BAYSOR_BENCH_DATA/baselines/bugfixes-35e8a7e/<dataset>/`, plus
  `vendor_audit.json` for the `*_admix` datasets (vendor segmentation scored
  on the baseline's typing and fixed pair set).

## Self-checks (expected outcomes)

| check | run | expect | outcome |
|---|---|---|---|
| fresh 6t/3rep run of 10 quick datasets (incl. 2 `*_admix`) vs this baseline | `chk-b-same` | `same` **PASS** | ✅ 74 passed / 0 failed |
| same run | `chk-b-same` | `improved` **FAIL** | ✅ exit 1 (aggregate gain below the 0.005 min effect; iss admixture above tolerance — an unchanged binary cannot pass) |
| `--scale-factor 0.9`, same subset | `chk-b-scale09` | `same` **FAIL on most** | ✅ exit 1: 14 failed gates across **6 of 10** datasets (all 6 real, plus `strec_dense_s2_disjoint`) |
| fresh 1t/1rep subset vs `bugfixes-35e8a7e-t1` | `chk-t1a` | `identical` **PASS** | ✅ 70 passed / 0 failed, all 10 `assignment_sha256` bitwise equal |
| `--scale-factor 0.9` 1t subset vs `-t1` | `selfcheck-t1-scale09` | `identical` **FAIL** | ✅ exit 1 |

Known issue recorded by this task: the first three 1-thread self-check
runs (run-ids `selfcheck-t1-fresh{,2,3}`) failed bitwise on
`iss_mouse_hippocampus_quick` and `osmfish_somatosensory_quick`. Root cause
(found by bisection, see [`../../harness/README.md`](../../harness/README.md)
→ "Determinism findings"): at 1 thread the binary's behaviour depends on the
length of the `-o` path — run-ids of ≥ 18 characters deterministically flip
those two datasets (7 stable runs at 11–17 chars vs 4 flipped runs at
18–19 chars; suspected undefined behaviour in Baysor, filed as a
follow-up). The official self-check with the short run-id `chk-t1a` passes.

See [`bugfixes-35e8a7e-t1/`](bugfixes-35e8a7e-t1/) for the exact 1-thread
baseline used by `--expect identical`.
